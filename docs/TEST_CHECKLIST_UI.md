# Test checklist — rebrand, accessible design, login (docs/CHANGE_PLAN_UI.md)

Manual checks for the SK EduKabataan redesign. You need one admin account, one applicant account, and one account
whose password has **no** special character (e.g. set an old one like `oldpass12` in the database, or use an account
created before this change). Numbered steps; "→" is what you should see. Use a recent Chrome, Edge or Firefox.

## 1. Name and logos
1. Open the landing page. → The browser tab says "SK EduKabataan: Educational Assistance for College Students" and
   shows the SK logo as its icon. The page shows the SK logo and the Barangay seal side by side, the name, the
   tagline and the subtitle "Sangguniang Kabataan · Barangay Estefania · Bacolod City".
2. Open Sign In. → Both logos side by side, the name, then "Sign in". The tab says "Sign In · SK EduKabataan".
3. Open Register, Forgot password, the OTP pages and a page that doesn't exist (e.g. `/nothing-here`). → Each shows
   the SK logo and the name; each tab title ends in "· SK EduKabataan".
4. Sign in. → The sidebar shows the SK logo (in a white circle) and "SK EduKabataan / Barangay Estefania"; the footer
   says "© <year> SK EduKabataan · …".
5. Hover over each logo image with a screen reader or inspect it. → Alt text "SK Barangay Estefania logo" and
   "Barangay Estefania seal".
6. Admin → Settings → Send test e-mail. → The e-mail's header is a dark blue band with "SK EduKabataan" and
   "Educational Assistance for College Students" in text (no image), a yellow line under it, and the footer says
   "This is an automated message from SK EduKabataan." It looks the same with images blocked.
7. Admin → Reports → any report as PDF. → The header shows both logos side by side, "SK EduKabataan", the tagline,
   the subtitle and the report title; the footer says "Generated by SK EduKabataan · Page n".

## 2. Sign In: empty fields
1. On Sign In, leave both fields empty and click **Sign In**. → Nothing is submitted (the page doesn't reload). A
   pop-up says "Please enter your email address and password." in large text, with an **OK** button that has focus.
   Each field gets a red border and a red message with an icon underneath ("Enter your email address.",
   "Enter your password.").
2. Press **Esc**. → The pop-up closes and the cursor is in the **Email** field.
3. Type an email, leave the password empty, click Sign In. → The pop-up says "Please enter your password."; press
   **OK** → the cursor is in the Password field. Typing in a field removes its red message.
4. Turn JavaScript off (or submit with it disabled) and sign in with both fields empty. → The page reloads with the
   same friendly message in a red box with an icon, and the same red messages under the fields — not
   "Invalid credentials".

## 3. Show / hide password
1. On Sign In type a password, put the cursor in the middle of it, then press **Tab**. → Focus moves to the eye
   button inside the field, with a thick visible outline. A screen reader reads "Show password, toggle button, not
   pressed".
2. Press **Space** (or Enter). → The password becomes readable, the icon changes to an eye with a slash, the label
   becomes "Hide password", and the text and cursor position are unchanged. Press it again → hidden again.
3. The eye button is on every password field: Register (both), Set a new password (both), My Profile (all three),
   Admin → Users → Add staff (both) and → Reset password (both).

## 4. Password rule (new and changed passwords only)
1. Register with password `password1` (and the same in Confirm). → While typing, the checklist under the field shows
   "At least 8 characters" ticked and "At least 1 special character (e.g. ! @ # $ %)" not ticked (an icon plus the
   word, not just a color); "Passwords match" ticks once both fields are equal. Submit → refused with
   "Your password needs at least 1 special character (e.g. ! @ # $ %)." in a red box and under the field; your name
   and email are still filled in; no account is created.
2. Register with `short!` → refused with "Your password needs at least 8 characters."
3. Register with `password1!` → accepted; you go on to e-mail verification.
4. Forgot password → enter the code → Set a new password with `password1` → refused with the same message; with
   `password1!` → accepted, and you can sign in with it.
5. Admin → Users → Add staff with `password1` → refused with the same message; with `password1!` in one field and
   `password2!` in Confirm → "The two passwords do not match."; with `password1!` twice → created.
6. Admin → Users → Reset password (key button) with `short` → "Your password needs at least 8 characters and at
   least 1 special character (e.g. ! @ # $ %)."; with a good one twice → "Password reset."
7. Applicant → My Profile → change password with `password1` → refused with the same message; a good one that
   doesn't match Confirm → "The two new passwords do not match."; a good one twice → "Profile updated." Saving the
   profile with the password fields empty still works.
8. **Old passwords still work:** sign in with the account whose password has no special character. → You are signed
   in normally. (The rule is never checked at sign-in.)

## 5. Text size, zoom and phone
1. Click **A+** then **A++** in the top bar (on phones: in the account menu; on auth pages: top right). → All text
   grows (115%, then 130%); the pressed button is highlighted. Go to another page and reload → the size is kept.
   Click **A** → back to normal.
2. With **A++** on, open every page in the sidebar. → Nothing overlaps or is cut off; no sideways scrolling of the
   page (wide tables scroll sideways inside their own card).
3. Set the browser zoom to **200%** (Ctrl and +). → The sidebar folds into the menu button; every page still reads
   top to bottom with no sideways page scroll.
4. Phone width **360px** (developer tools → device toolbar, or a real phone): Sign In, Register, landing page,
   dashboard, application form and the admin lists. → No sideways page scrolling; buttons and fields are full width
   and easy to tap.

## 6. Keyboard and focus
1. On Sign In, press **Tab** repeatedly from the top. → First "Skip to main content" appears, then A / A+ / A++,
   Email, Password, the eye button, "Forgot password?", Sign In, "Register as an applicant", "Back to home". Every
   one shows a thick (3px) outline: dark blue on light backgrounds, yellow on the blue background.
2. Signed in, Tab through the sidebar. → Each menu item shows a yellow outline; the current page is marked with a
   yellow bar on the left.
3. Icon-only buttons (search, clear filters, edit, delete, reset password, close ×) are announced by name by a screen
   reader (e.g. "Search", "Clear filters", "Edit budget", "Close").
4. Turn on "reduce motion" in the operating system. → No fades, slides or pulsing dots anywhere.

## 7. Readability and color
1. Body text is dark (near-black) on white or very light gray; no light-gray text anywhere; the smallest text (dates,
   hints, badges) is still comfortably readable (at least 15px).
2. Status badges (Approved, Returned, Rejected, Waitlisted, Uploaded, Verified, …) show the **word** on a pale
   background with dark text; none rely on color alone.
3. Yellow appears only as accents (sidebar active bar, the line under the brand, the current step ring, focus outline
   on blue) — never as text and never behind text. The calendar's "today" cell is pale blue with a yellow bar on top.
4. Red is used only for errors and destructive buttons (delete, reject, end scholarship).
5. Every field has a visible label above it, including the search boxes and dropdowns at the top of the admin lists.

## 8. Font (system font, aligned numbers)
1. On Windows the whole site (headings, text, fields, tables) is in Segoe UI; on an iPhone/Mac it is San Francisco;
   on Android, Roboto. Nothing is downloaded for fonts (developer tools → Network → filter "font": only the icon font).
2. Admin → Budget, Releases, Claims, Dashboard, Analytics: zeros are plain (no slash) in every ₱ amount, and amounts in
   the same column line up digit by digit.
3. Charts (Dashboard, Analytics) and the Calendar use the same font as the rest of the page.
4. A test e-mail uses Segoe UI where available (Arial elsewhere); PDF reports keep DejaVu Sans so the ₱ sign prints.
